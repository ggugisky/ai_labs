# Connect AI

> Source: [Connect AI GitHub repository](https://github.com/wonseokjung/connect-ai)
> Meeting: [[raw/meeting/20260821]]

## 한줄 요약

Connect AI는 VS Code·Cursor·Antigravity 안에서 로컬 모델을 사용해 파일 생성, 코드 수정, 터미널 실행, 지식 구조화를 수행하는 확장형 AI 코딩 에이전트다.

## 핵심 기능

- Ollama와 LM Studio를 통한 로컬 모델 연결
- 파일 읽기·생성·수정, 디렉터리 탐색, 터미널 명령 실행
- 원시 입력을 Markdown 위키와 폴더 구조로 정리하는 지식 관리 흐름
- 설치된 로컬 모델을 자동 감지해 선택하는 모델 카탈로그
- GitHub 자동 동기화 기능
- VS Code 확장 프로그램 기반 UI

## 하네스 관점의 구조

Connect AI의 핵심은 특정 모델보다 모델을 작업 환경에 연결하는 하네스 계층이다.

1. IDE가 사용자 요청과 프로젝트 파일을 제공한다.
2. Ollama 또는 LM Studio가 로컬 모델 추론을 담당한다.
3. 에이전트가 파일·터미널 도구를 사용해 실제 변경을 수행한다.
4. 결과를 Markdown 지식 구조와 Git 저장소에 남긴다.

이 구조는 AI를 채팅창에 가두지 않고, 프로젝트 파일·명령 실행·지식 저장까지 하나의 작업 루프로 묶는 방식이다.

## 미팅에서 확인된 사용 방식

성환님은 Connect AI의 에이전트 팀 구조를 확장해 CEO, 비서, 개발자, 작가, 디자이너, 리서처 등 역할별 에이전트를 구성했다. 에이전트마다 프롬프트, 스킬, 도구, 메모리를 분리하고 CEO가 업무를 배분하는 방식이다.

다만 소개된 실제 환경에서는 로컬 모델의 컨텍스트 윈도우와 성능 한계 때문에 Google AI Pro 기반 모델도 함께 사용했다. 따라서 `Connect AI = 항상 순수 로컬만 사용`이라고 이해하기보다, 로컬 모델을 기본으로 하되 필요에 따라 외부 모델과 도구를 조합할 수 있는 확장 기반으로 보는 편이 정확하다.

## 장점

- 민감한 코드와 지식을 로컬 중심으로 처리할 수 있다.
- IDE, 파일, 터미널이 한 작업 흐름 안에 들어온다.
- 모델과 지식 저장 방식을 사용자가 직접 바꿀 수 있다.
- Markdown·Git 기반이라 지식의 이동성과 가시성이 높다.
- 개인 하네스나 에이전트 팀으로 확장하기 쉽다.

## 한계와 주의점

- 로컬 모델 품질은 하드웨어와 모델 크기에 크게 좌우된다.
- 터미널·파일 삭제·Git push 권한을 부여하면 에이전트의 실행 범위가 넓어진다.
- 자동 Git 동기화는 편리하지만 잘못 생성된 내용이나 비밀정보가 저장소에 올라갈 위험이 있다.
- 실패한 작업 기록을 지식으로 재사용하지 않도록 검증·승격 규칙이 필요하다.
- 저장소 README의 기능 설명과 실제 확장 프로그램 버전은 달라질 수 있으므로 설치 전 최신 릴리스를 확인해야 한다.

## AI Labs 시사점

Connect AI는 AI Labs가 실험하는 개인 하네스와 가장 직접적으로 연결되는 사례다. 특히 `raw → wiki → skills` 구조, 로컬 모델 선택, 에이전트별 메모리 분리는 현재 AI Labs의 LLM Wiki 운영 방식과 비교해 볼 가치가 있다.

다음에 확인할 질문은 다음과 같다.

- 자동 Git sync 전 승인 단계를 어디에 둘 것인가?
- 실패한 기록과 검증된 지식을 어떻게 분리할 것인가?
- 로컬 모델과 클라우드 모델을 작업 유형별로 어떻게 라우팅할 것인가?
- 에이전트별 권한과 파일 접근 범위를 어떻게 제한할 것인가?
