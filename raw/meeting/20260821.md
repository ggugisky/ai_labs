## Summary

## 1. 이번 미팅의 핵심

성환님이 개인적으로 구성한 멀티 에이전트 하네스와 이를 활용한 정치·시사 유튜브 쇼츠 자동화 사례를 소개했다. 단순히 AI 도구를 사용하는 수준을 넘어, 여러 전문 에이전트가 역할을 나눠 하나의 콘텐츠 제작 회사를 운영하는 형태를 실험하고 있었다.

이번 영상에서는 Claude Tag, Pi, xAI Bot, Aside를 별도로 깊게 분석하기보다는 하네스 소개와 실제 서비스·제품화 사례에 대부분의 시간을 사용했다.

## 2. 성환님 하네스 소개

### 2.1 기본 개념

- `connect-ai`를 기반으로 한 에이전트 팀 구조
  - Repository: https://github.com/wonseokjung/connect-ai
- 에이전트마다 역할, 프롬프트, 도구, 메모리를 분리한다.
- CEO 에이전트가 사용자의 요청을 해석하고 적절한 전문 에이전트에게 업무를 배분한다.
- 작업이 끝나면 각 에이전트의 결과를 취합해 사용자에게 보고한다.
- VS Code 계열 확장 프로그램으로 실행할 수 있어 접근성이 높다.

### 2.2 에이전트 구성

소개된 팀에는 CEO, 비서, 개발자, 유튜브 담당자, 디자이너, 작가, 리서처, 음악 담당자, 비즈니스 전략 담당자 등 약 10개의 전문 에이전트가 있다.

- CEO: 요청을 해석하고 업무를 오케스트레이션하며 최종 결과를 보고
- 비서: Google Calendar와 Telegram을 이용해 일정·진행 상황을 관리
- 유튜브 담당자: 채널·영상 수집, 업로드, 태그 및 성과 분석
- 작가: 요약 대본, 내레이션, 장면 구성 작성
- 디자이너: 대본에 맞는 이미지와 영상 에셋 생성
- 개발자: 이미지·대본·음성을 영상으로 조립하는 파이프라인 실행
- 리서처/비즈니스 전략 담당자: 시장 조사와 수익·성장 방향 제안

### 2.3 모델과 도구 운영

- 처음에는 로컬 LLM 중심으로 구성했지만, 로컬 모델의 컨텍스트 윈도우와 성능 한계 때문에 현재는 Google AI Pro를 활용해 Gemini 3.7 계열 모델을 주로 사용한다.
- 에이전트별로 모델을 다르게 지정할 수 있다.
  - 단순 정리·분류에는 저렴한 모델
  - 전략 수립·복잡한 판단에는 상대적으로 강한 모델
- Google Flow는 직접 API 호출이 어려워 MCP를 통해 영상 생성 기능을 연결했다.
- YouTube, Telegram, PayPal, Google Calendar 등 외부 서비스와 연동할 수 있는 구조다.
- 세션별 작업 내용과 에이전트 간 통신은 파일과 Markdown 보고서로 기록된다.
- 에이전트의 작업 결과를 지식 그래프로 시각화하는 기능도 있으나, 원하는 지식 검색·재활용 수준까지는 추가 구현이 필요하다.

### 2.4 파일·메모리 구조와 한계

각 에이전트의 스킬, 프롬프트, 도구, 목표, 메모리를 폴더 단위로 나눠 관리한다. 세션마다 CEO 브리프와 비서의 종합 리포트도 남는다.

다만 과거에 실패한 작업 기록까지 재사용하는 문제가 있어, 실패한 패턴을 자동으로 배제하고 검증된 지식만 축적하는 구조는 아직 보완이 필요하다. PDF나 책을 기반으로 질문·답변 데이터를 자동 생성해 로컬 모델을 파인튜닝하는 기능도 소개됐지만, 아직 본격적으로 사용하지는 않았다.

## 3. 실제 적용 사례: `모두의 개소리`

### 3.1 서비스 아이디어

정치·시사 유튜버들이 올린 영상을 수집하고, 최근 이슈를 요약해 쇼츠로 제작하는 자동화 채널이다. 유튜브를 직접 모두 시청하기 어려운 사람에게 여러 채널의 주요 이슈를 짧게 전달하는 것이 목적이다.

장기적으로는 개인 채널용 도구가 아니라 기업의 콘텐츠 마케팅 비용을 줄여주는 B2B 서비스로 확장하는 방향을 생각하고 있다.

### 3.2 콘텐츠 제작 파이프라인

1. 유튜브 담당 에이전트가 등록된 채널 목록을 읽는다.
2. 전날 업로드된 영상을 수집하고 조회수·좋아요 등 데이터를 정리한다.
3. 작가 에이전트가 이슈를 요약하고, 대본·내레이션·장면별 연출을 작성한다.
4. 디자이너 에이전트가 장면별 이미지와 영상 에셋을 생성한다.
5. 개발자 에이전트가 에셋, 대본, TTS를 Google Flow 등과 연결해 영상을 만든다.
6. 사용자의 확인을 거친 뒤 영상과 쇼츠를 비공개로 업로드한다.
7. 유튜브 담당 에이전트가 제목·태그를 붙이고 성과를 분석한다.
8. 24시간 운영 기능을 켜면 채널 성과와 초기 목표를 비교해 다음 콘텐츠 방향을 제안한다.

### 3.3 현재 결과와 문제점

- 에이전트들이 데이터 수집부터 영상 생성·업로드·분석까지 실제로 연결되어 동작한다.
- 하지만 영상의 연출, 자막, 이미지 품질이 아직 낮고 결과물의 일관성도 부족하다.
- 무료 또는 저가 모델을 사용하면 한국 정치 콘텐츠에 맞지 않는 이미지가 생성되는 등 모델의 데이터 편향 문제도 나타났다.
- 자동 검수 에이전트가 결과물을 통과시켜도 사람이 보기에는 품질이 낮은 경우가 있었다.
- 채널·영상 선정 과정에서 저작권, 명예훼손, 정치적 편향 및 법적 리스크를 계속 필터링해야 한다.
- 고품질 영상 모델은 비용이 높아, 품질과 생성 비용 사이의 균형이 필요하다.

## 4. 미팅 중 논의된 개선 방향

### 4.1 콘텐츠 품질 개선

- 모델만 교체하기보다 작가 에이전트의 스킬을 강화하는 방향이 중요하다.
- 글로벌 유튜버의 대본·연출·전달 방식을 분석해 작가 스킬로 반영하는 아이디어가 나왔다.
- 자극적인 콘텐츠가 필요하더라도 무리한 실존 인물 묘사보다는 일관된 가상 아바타나 풍자적 캐릭터를 사용하는 방안이 제안됐다.
- 정치 콘텐츠를 단순 편집·요약하는 것을 넘어, 여러 출처를 비교하는 팩트체크 에이전트로 확장할 가능성도 논의됐다.

### 4.2 제품화 가능성

성환님의 파이프라인은 유튜브 자동화뿐 아니라, 시장에서 인기 있는 영상 형식·폰트·카피·연출을 분석해 기존의 긴 영상을 숏폼 콘텐츠로 재편집하는 콘텐츠 마케팅 플랫폼과도 연결될 수 있다는 의견이 나왔다.

즉, 이번 사례의 핵심은 `AI가 영상을 하나 만들어 준다`가 아니라 `시장 조사 → 형식 분석 → 대본·에셋 생성 → 편집·배포 → 성과 분석`을 에이전트 팀으로 자동화하는 데 있다.
