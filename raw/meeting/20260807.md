- 실제 진행 내용:
  - `용욱님 하네스`는 개인 하네스와 실제 서비스가 어떻게 이어지는지 보여주는 소개였다.
  - `dalar`와 `lampas` 같은 서비스 사례를 함께 보면서, 하네스를 제품이나 서비스로 확장할 때 어떤 구성이 필요한지 설명했다.
  - 로컬 환경에서 모델을 쓰는 방식, Claude의 모델 자동 선택, 작업을 위키화해서 남기는 방식, 비용 관리 같은 실사용 관점 이야기가 나왔다.
  - 영상 중간에는 실제 서비스 예시를 보여주며, 템플릿화와 이미지/영상 요소 결합 같은 확장 방향도 공유했다.

#### Dalar 분석

- Dalar는 `프롬프트를 잊고 대화로 만드는` 방식의 크리에이티브 AI 서비스로 소개됐다.
- 공식 설명상 사진 한 장에서 사람, 상품, 공간을 기억하고 이를 브랜드 콘텐츠로 이어주는 흐름이 핵심이다.
- 녹화본에서는 다음 포인트가 강조됐다.
  - 이미지 한 장이나 간단한 입력에서 시작해 결과물을 만들어내는 방식
  - 프롬프트를 직접 조합하기보다 대화형으로 요청을 수집하는 방식
  - 레퍼런스를 유지한 채 콘텐츠를 반복 생성하는 구조
  - 브랜드가 필요한 사용자를 위해 사진, 텍스트, 이미지, 영상 요소를 함께 묶는 방향
- 실무 관점에서 보면 Dalar는 `에이전트`라기보다 `브랜드 콘텐츠 생성 스튜디오`에 가깝고, 하네스가 실제 수익형 서비스로 확장될 때 어떤 UI와 작업 흐름이 필요한지 보여주는 예시였다.

#### Lampas 분석

- Lampas는 `생성형 AI로 수익을 만드는 가장 빠른 방법`이라는 포지셔닝으로 소개됐다.
- 공식 설명과 녹화 내용 모두, 이미지와 비디오 모델을 노드로 연결해 파이프라인을 실험하고, 잘 되는 조합만 앱에 넣는 구조가 핵심이다.
- 녹화본에서는 다음 포인트가 강조됐다.
  - 노드 기반으로 이미지, 비디오, 편집 단계를 조합하는 방식
  - 모델을 직접 조립해 파이프라인을 만들고, 결과가 좋은 조합을 다시 서비스화하는 방식
  - 크레딧이나 결제 흐름을 붙여 실제 사용량 기반으로 운영하는 구조
  - 브랜드/상품/공간 같은 입력을 반복 가능한 콘텐츠 제작 파이프라인으로 바꾸는 방향
- 실무 관점에서 보면 Lampas는 `실험용 모델 조합기`와 `상용 서비스` 사이에 있는 형태다.
- 그래서 이번 회의에서는 Lampas가 단순 데모가 아니라, 하네스가 곧 제품 파이프라인이 되는 구조를 보여주는 사례로 다뤄졌다.
