## 발표 내용

이번 발표는 AI를 개발 보조 도구로 사용하던 단계에서 출발해, 직접 에이전트와 음성 인터페이스를 만들고 원격 제어 환경을 구성한 뒤, 현재는 개인에게 필요한 실행 환경 자체를 설계하게 된 과정을 공유한다.

### 1. 하네스 변천사

- GitHub Copilot과 Windsurf를 사용하며 AI를 코드 작성·수정에 활용했다.
- 2024년 GPT-4 기반 Confluence RAG 챗봇과 LangChain/LangGraph 기반 Scarlett을 개발하며 검색 품질, 컨텍스트, 실행 상태 관리의 중요성을 경험했다.
- 2025년 EAK MCP를 개발하면서 최신 업무 데이터와 사내 기능을 에이전트에 연결했지만, MCP 설정 허들이 확산의 큰 장애물이라는 점을 확인했다.
- 2025년 12월부터 2026년 6월까지 총 7회의 바이브 코딩 세션을 진행했고, 약 100명의 EA Korea 스튜디오 구성원이 MCP와 에이전트 기반 개발을 경험했다.
- 음성 에이전트 실험과 OpenClaw 사용을 거쳐 모바일·음성 클라이언트인 파랑을 만들었다.
- OpenClaw의 풍부하지만 복잡한 기능에서 벗어나, 필요한 기능만 직접 설계한 Margaret Gateway로 발전시켰다.

### 2. Margaret Gateway 구성

Margaret Gateway는 Claude Code, Codex, OpenCode 같은 로컬 CLI 에이전트와 Slack·음성 앱·Web UI·CLI를 연결하는 개인용 게이트웨이이자 하네스다.

- FastAPI, SQLite, 순수 Python 기반 REST + SSE 게이트웨이
- 여러 실행기와 클라이언트가 하나의 세션을 공유
- 네이티브 CLI 세션 바인딩을 통한 대화 맥락 유지
- 선택적인 장기 기억과 Semantic Memory 주입
- 명령 전달, 세션 관리, 실행 결과 전달을 하나의 제어 계층에서 처리

핵심 구조는 `brain + policy + memory + approvals → Margaret Gateway → Codex / Claude Code / OpenCode / OpenClaw`로 정리한다. 실행기를 하나로 합치는 것이 아니라, 공통 정책·기억·세션·승인을 통합하고 각 실행기는 어댑터로 유지하는 방향이다.

### 3. 파랑과 마가렛의 관계

- OpenClaw: 기능이 풍부한 범용 에이전트 플랫폼
- 파랑: OpenClaw를 모바일·음성으로 사용하기 위한 맞춤형 클라이언트
- 마가렛: 여러 로컬 에이전트와 클라이언트를 연결하고 필요한 기능을 직접 설계한 개인용 하네스 게이트웨이

파랑은 실패해서 버린 시스템이 아니라, 실제 사용 경험을 바탕으로 더 단순하고 개인에게 맞는 구조를 만들기 위한 발전 단계다.

### 4. GPT 음성·Work와의 비교에서 얻은 점

최근 GPT 음성·Work 기능을 사용하면서, 모델의 지능만큼 클라이언트의 실행 오케스트레이션, 장시간 작업, 컨텍스트 유지, 세션 지속성이 중요하다는 점을 확인했다. 복잡한 업무가 중단되거나 맥락을 잃는 문제를 모델 자체의 한계로 단정하기보다 모델·클라이언트·도구 권한·세션 관리가 함께 만든 결과로 봐야 한다.

Margaret의 차별점은 음성 호출 자체가 아니라, 어떤 모델과 에이전트를 사용하더라도 개인의 작업 공간·기억·규칙·세션을 유지하면서 복잡한 일을 끝까지 진행할 수 있는 실행 환경을 만드는 데 있다.

### 5. 보이스 퍼스트의 방향

보이스 퍼스트의 핵심은 AI와 대화할 수 있다는 사실이 아니라, 말로 시작한 생각이 실제 문서·코드·업무 결과물로 이어지는 것이다. 파랑과 마가렛은 산책하거나 이동하는 생활 속에서 음성으로 아이디어를 말하고 결과물을 만들어가는 방식을 먼저 실험한 사례다.

> 보이스 퍼스트의 미래는 AI에게 말할 수 있는 미래가 아니라, 말로 시작한 생각이 실제 결과물로 이어지는 미래다.
