# Yuil AI Labs 발표 분석

## 범위와 출처

2026-09-04 AI Labs 발표 녹화(`AI LABS - EPISODE 4`)와 저장소에 반영된 발표자료의 발표자 노트를 대조해 정리했다. 아래의 수치와 진행 상황은 발표자료에 기재된 발표자 설명이며, 외부 검증을 거친 독립 통계로 보지 않는다.

## 핵심 주장

발표의 중심 주장은 “AI가 생성과 정리를 흔한 일로 만들수록 실제 효과를 판별하는 능력이 희소해진다”는 것이다. 지난 2년의 여러 실험에서 재사용 가능한 다섯 블록을 추출하고, 이를 `수집 → 정리 → 생성 → 배포 → 측정과 학습` 엔진으로 조립해 측정을 전제로 한 맞춤형 마케팅 솔루션으로 확장하려는 제안이다.

## 발표에서 확인된 내용

### 멍미와 데이터 제품화

- 4~12세 반려동물 보호자가 사료 성분과 안전성을 판단하기 어려운 문제를 다룬다.
- 농사로·식약처·농관원·openFDA·제조사 사이트에서 데이터를 배치 수집하고, 안전·주의·위험 3단계로 판정한다.
- 브랜드 식별은 LLM 추정에서 사전 기반 방식으로 전환했다.
- 추천글 생성, 품질 필터, 4개 쇼핑몰 가격 추적, 단종 상품 재연결을 자동화했다.
- 발표자료 기준으로 성분표 확보율은 2.5%에서 100%로 개선됐고, 8,200개 사료 분석·99% 성분 검증·340개 원료 사전·4가지 건강 지표를 제시했다.
- 핵심 교훈은 생성보다 최신 데이터의 수집·정합성·유지가 운영 병목이라는 점이다.

### 재사용된 리콜차트 패턴

리콜 주당 8.7건, 상품명 매칭 98%라는 사전 검증 결과를 바탕으로 6일 만에 리콜차트를 만들었다고 설명했다. 모든 판정은 정부 공시 원문을 인용하고, 멍미에서 얻은 링크 유실 3중 방어를 이식했다. 따라서 빠른 개발의 원인은 생성 속도보다 착수 전 검증과 방어 코드의 재사용으로 해석된다.

### 다른 블록에서 반복된 운영 원칙

- 실패 조건을 먼저 적고 수치로 게이트를 통과시킨다.
- 추정값은 사전으로, 품질 검증은 골든셋으로, 비즈니스 로직은 결정론적 코드로 관리한다.
- 역할·인수인계·회귀 테스트·드리프트 점검까지 포함해야 AI 도구가 아니라 운영 체계가 된다.
- 실패한 PoC도 다음 프로젝트의 부품으로 남긴다.

### 제안된 여섯 번째 블록

용욱님의 콘텐츠 생성·운영 자동화 솔루션 위에 주장 단위 검증, 실험 설계, 인크리멘탈리티, 세그먼트·리텐션 분석을 결합한다. 고객 데이터의 존재·품질·접근성을 먼저 확인한 뒤 니즈 정의, 측정 설계, 콘텐츠 구성, 근거·인사이트 리포트 순으로 진행한다. 고객에게 제공할 증명은 “맞고 안전한가”와 “성과에 기여했는가” 두 가지다.

## 사업화 가설과 게이트

- 고객군은 대형 공식 SNS 운영 조직, 시리즈 A 이전 스타트업, 온라인 제품·서비스 기업의 세 단계로 제시됐다.
- 무료·저가 경험으로 신뢰를 만든 뒤 분석가의 추천을 통해 마케팅 의사결정권자와 고가 계약으로 연결하는 사다리를 구상한다.
- 진행 중인 사례로 콘텐츠 마케팅 비딩, 모두의소리 Snowflake 빌드, Databricks 프로젝트 협의를 언급했다.
- 담론레이더는 2026-10-25 수요 검증, 여섯 번째 블록은 2026년 12월까지 유료 파일럿 1건과 측정 리포트 1건을 판단 기준으로 둔다. 미달 시 종료 또는 재설계한다.

## AI Labs 적용 제안

1. 멍미의 `원천 → 사전/판정 → 근거 인용 → 추천` 흐름을 표준 데이터 제품 템플릿으로 문서화한다.
2. 모든 신규 프로젝트에 착수 전 실패 조건, 검증 수치, 중단 기준을 기록한다.
3. 모두의소리 또는 다음 파일럿에 콘텐츠 단위 무작위 배정, UTM, 사전 등록 지표를 적용해 측정 블록을 검증한다.
4. 발표 수치는 원자료·표본·측정 정의를 함께 보관하고, 외부 공개 전 독립 검증 상태를 표시한다.
