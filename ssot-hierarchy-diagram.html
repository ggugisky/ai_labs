AGENTS.md — LLM 운영 규칙

LLM이 이 저장소에서 어떻게 행동해야 하는지 정의 · 스킬·승격 기준·일일 점검 절차 포함

AGENTS.md 핵심 스킬 3종
/promote
raw 파일 → wiki 승격 자동화.
승격 판단 → wiki 생성 → raw 헤더(status: promoted) 업데이트 → index.md 링크 추가 → log.md 이력 기록 → GitLab 커밋
/wiki-lint
깨진 링크 · 노후화 문서 · source_url 누락 · promoted 헤더 불일치 · 중복 내용 일괄 점검
/confluence-sync
snapshot_at vs Confluence Last Modified 비교 → 신규 페이지 감지 → raw 수집 → wiki 반영.
일일 점검 절차: ① git pull → ② 승격 후보 점검 → ③ confluence-sync → ④ wiki-lint → ⑤ 커밋 push

왜 lint & promote를 스케줄로 실행해야 하나?

사람이 매일 점검하지 않으면 지식 저장소는 빠르게 부패한다

수동 점검의 한계 — "나중에 해야지"는 결국 안 한다
문제 1
깨진 링크 누적
[[wiki/pedro-design-screens]] 처럼 deprecated된 파일 링크가 방치되면 LLM이 없는 문서를 참조
문제 2
raw 파일 방치
재사용 가치가 생긴 draft 파일이 raw에 묻혀 wiki로 승격되지 않으면 지식이 단절됨
문제 3
Confluence 내용 drift
원본이 바뀌었는데 wiki는 구버전 내용 그대로 → LLM이 오래된 정보로 답변
해결 — cron이 하루 3번 자동 실행
08:00
하루 시작 전 상태 점검 — 전날 변경사항 반영 여부 확인
14:00

20:00
하루 마감 점검 — 당일 변경사항 커밋 · push, 저장소 최신 상태 유지
